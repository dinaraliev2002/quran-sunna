# Приложение «Коран и Сунна» (Android, v3.60) — как устроен плеер

Разобрано 12.11.2026 по `koran-i-sunna_v3.60_ApkTake.com.apk` (рабочий стол). Приложение на Kotlin, тексты в зашифрованном архиве `assets/dosh.to1`; аудио в APK нет — качается.

## Откуда аудио и как устроено
- Аудио — **файлы отдельных аятов** с everyayah.com: в ресурсах лежат имена папок (`Alafasy_128kbps`, `Husary_128kbps`…) — ровно такая же схема, как была у нас до цельных записей. Цельных записей сур у них нет.
- У большинства чтецов **два-три качества** (кбит/с): 192/128/64/32 — пользователь выбирает в настройках и видит объём («114 сур … чем выше битрейт, тем больше места»). Скачивание по сурам на телефон («Mountains 282Mb↓»).
- Склейки не нужны: файлы играют подряд; в ресурсах есть отдельные записи «Бисмиллах» (`basmallah*.mp3`) — басмала вставляется перед сурой.
- Есть настройки: пауза между аятами, повтор аята/нескольких аятов, переход на следующую суру, чтение по словам.

# Приложение «Академия Корана» (org.quranacademy.quran 1.9.9) — как устроено аудио

Разобрано 12.11.2026 по `org.quranacademy.quran_1.9.9.xapk` (рабочий стол); без аудио в пакете, всё идёт с их сервера.

- **Список чтецов** — с сервера `https://api.quranacademy.org/quran/audio/recitations` (нужен заголовок `Locale: ru`), 42 записи: `id`, `name`, `url_template`, `timecodes_file`.
- **Аудио — файлы отдельных аятов**: `https://quran-audio.quranacademy.org/by-ayah/<Папка_чтеца>/{sura}/{ayat}.mp3` (своё хранилище, DigitalOcean Spaces + Cloudflare; папки названы как на everyayah, качества 128/192/64/…; файлы закрыты — без приложения отвечают 403, обходить не нужно). Цельных записей сур у них нет: плеер (ExoPlayer) играет плейлист из файлов аятов подряд.
- **Разметка** — у 14 чтецов (Шатри 10, Афаси 14, Хусари 22/24, Шурайм 56, Миншауи 30/31, Абдульбасит 4/5, Рифаи 20, Таблауи 32 и др.) файл `…/recitation-timecodes/<id>-v1-2020-06-13….db` (SQLite, таблица `recitation_timecodes(surah, ayah, word, start_time, end_time)`) — это **время слов внутри файла аята** (мс от начала файла аята), для подсветки слова. Границ аятов в цельной записи у них нет вообще, потому что нет цельной записи.
- **Вывод про «мощную нарезку»:** сверил Шатри 55:1–8 с everyayah — длительности и начало голоса совпадают (звук 37–54 мс от начала, конец файла вплотную к речи). То есть файлы, по сути, те же everyayah, никто их вручную не резал. Ощущение «цельно, без пауз» даёт плейлист из готовых файлов аятов (граница аята = граница файла, подсветка точна), а не особая нарезка. В слитных местах (Шатри 55:3|4) граница в самих файлах стоит посреди речи — у них, как и у нас, первая буква следующего аята может оказаться в конце предыдущего файла.
- **Как сделать «свою» чёткую нарезку:** (1) границы по провалам звука в цельной записи — `scripts/refine-boundaries.py` (сделано для Шатри); (2) для самого точного — нарезать записи на файлы аятов по этим границам и хранить у себя (Cloudflare R2 бесплатно до 10 ГБ, без платы за трафик; весь Коран у одного чтеца ≈ 0,5–1,5 ГБ); (3) играть файлы аятов встык через Web Audio, как сейчас у Афаси (`lib/glueAudio.ts`).
